## 주요 학습 내용

- **확률적 생성과 환각:** LLM은 사실을 조회하지 않고 다음에 올 확률이 높은 토큰을 생성한다. "예산은 ___만 원" 같은 문장 틀이 있으면 원문에 없어도 숫자를 채우기 쉽다. 그래서 프롬프트는 환각을 줄일 뿐 막지는 못하고, "확인 필요 + 확인처"로 사람이 검증할 지점을 드러내는 설계가 필요하다.
- **Zero-shot / Few-shot / 단계적 추론:** Zero-shot은 모델 비교용 기준선, Few-shot은 형식과 "확인 필요" 판단 기준 고정, 단계적 추론(확정/잠정 먼저 분리)은 v1의 조용한 정보 왜곡을 없앴다. 추론 과정은 노출하지 않고 핵심 근거 3개만 남겨 길이를 통제했다.
- **평가 축과 사전 규칙:** 결과를 보기 전에 가중치와 탈락 조건을 정해 두어야 "느낌"이나 이미 쓰고 있는 모델 쪽으로 결론이 끌려가지 않는다.
- **근거를 보이면 검증이 쉬워진다:** 10턴 로그 Turn 6의 공휴일 누락 오류는 AI가 계산식을 함께 보였기 때문에 사용자가 바로 찾아냈다.
