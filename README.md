# GenAI 기초 1: LLM 기반 업무 자동화 — 회의록 요약 어시스턴트 "노트지기"

"LLM 기반 업무 자동화" 미션의 결과물입니다. **회의록 요약** 과업을 Claude 계열 3종(Opus / Sonnet / Haiku)에 같은 입력으로 수행시켜 비교하고, 페르소나 기반 시스템 프롬프트를 설계한 뒤 단계적 추론 유도·Few-shot의 효과를 실제로 실행해 확인하고, 환각 검증 17문항과 16턴 대화로 검증한 과정을 정리했습니다.

## 이 저장소의 실행 결과는 어떻게 만들어졌나 (읽기 전에)

- **모든 실행 결과는 2026-10-12 Claude Code 세션에서 서브에이전트(`Agent` 도구)로 실제 실행**한 것이고, 입력·출력 원문은 `raw/runs/`에 있습니다(입력 63개, 출력 85개).
- **정답 기준은 실행 전에 먼저 커밋**했습니다(`raw/runs/00_preregistration.md`). 채점은 모델명·조건을 가린 별도 심사 에이전트가 했고, 익명화 키와 심사 원문도 공개합니다(`raw/runs/judge/`).
- 한계: ① 웹 UI·API가 아니라 Claude Code 서브에이전트 환경입니다(프롬프트 "없음"이 빈 상태와 같지 않음). ② 모델 정확한 ID와 생성 설정은 기록하지 못했습니다. ③ **ChatGPT·Gemini는 실행하지 못해 비교에서 제외**했습니다(이전 버전에 있던 두 모델의 출력은 실행 없이 작성한 것이라 삭제). ④ 대부분 조건당 1~3회 실행이라 통계적 결론이 아닙니다. 자세한 이탈·변경 내역은 `raw/runs/99_run_notes.md`.
- 시스템 프롬프트·Few-shot·입력 템플릿(`prompts/`)은 사람이 설계한 자산이고 모델 출력이 아닙니다.

## 선택한 업무 과업

**회의록 요약** — 회의 메모를 받아 `결정사항 / Action Items / 리스크·이슈 / 확인 필요 / 후속 일정` 형식으로 정리한다. 확정과 잠정을 구분하고, 원문에 없는 수치는 만들지 않고 "확인 필요 + 확인처"로 표기한다.

## 실측 결과 요약

| 항목 | 결과 |
|---|---|
| 모델 비교 (Zero-shot, 블라인드) | Opus 4.69 / Haiku 4.63 / Sonnet 3.85 (가중 합계). **Opus와 Haiku 차이 0.06점으로 사실상 동률**이고, 형식 축(③)을 빼면 Sonnet이 최고. 선정은 근소 우위 + 사후 추가 규칙에 의존 |
| v1(프롬프트 없음) vs v2.1 (Opus) | Opus는 v1에서도 잠정·미상 정보를 왜곡하지 않음. v2.1의 확인된 이득은 형식 고정·날짜 환산·확인처 명시 |
| 소형 모델 (Haiku) | 프롬프트 없음: "다음 주 화요일"을 10/14로 **오환산**(T3 0/2). v2.1: 2/2. 5줄 압축(날짜 규칙 누락): 1/2 |

| 16턴 대화 (Opus, v2.1) | 조건부 Pass: 실명 금지·형식·수치 유지, 환각 유도 거부. **어조 변경은 약하게 반영**, **원문에 없는 문장 1건이 최종본까지 유지**(자기 점검이 못 잡음) |
| 상태 블록(04 Q3) | 변경 추적·어조 반영 개선, 근거 없는 문장은 못 막음, 응답 길이 1.45배 |

## 주요 학습 내용

- **확률적 생성과 환각:** LLM은 사실을 조회하지 않고 다음에 올 확률이 높은 토큰을 생성한다. 이번 실행에서 Fail이 나온 유형은 근거 없는 **미래 예측 수치**("약 3,000건")였고, 문장 틀이 있으면 숫자를 채우는 경향과 일치한다. 반면 근거 자료가 있는 질문은 최신 모델이 프롬프트 없이도 잘 처리했다.
- **프롬프트 기법의 효과는 모델 크기에 따라 다르다:** Opus에서는 형식·확인처 개선 정도였고, Haiku에서는 날짜 환산 정확도에서 차이가 났다. 압축 프롬프트에서 규칙 하나를 빼면 그 기능이 사라진다.
- **효과를 입증하지 못한 것도 기록한다:** v2.1 공휴일 규칙의 추가 효과는 입증되지 않았고, 모델의 자기 점검은 근거 없는 문장을 잡지 못했다.
- **사전 등록과 블라인드 채점:** 정답 기준을 먼저 고정하고 채점자에게 모델명을 가리면 "내가 만든 프롬프트가 잘 동작한다"는 확증 편향을 줄일 수 있다.
