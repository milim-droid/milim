# 실행 중 관찰된 이탈과 사전 등록 대비 변경 사항

## 1. 서브에이전트의 지시 이탈 (자진 보고 기준)

서브에이전트에는 "입력 파일 1개 읽기 + 출력 파일 1개 쓰기만 허용, 그 밖의 도구 사용 금지"를 지시했다. 아래 3건은 서브에이전트가 스스로 보고한 이탈이다. 모두 읽기 전용이고 결과는 응답에 사용되지 않았다고 보고했으며, 출력 내용에 영향이 없는 것으로 판단한다. 보고하지 않은 이탈이 있었는지는 확인할 수 없다.

| 실행 | 보고 내용 |
|---|---|
| `Hk_none_2` (Haiku, 프롬프트 없음 2회차) | 요청하지 않은 `list_sessions` 호출 2회. 결과 미사용 |
| `X3_v21_haiku` (Haiku, v2.1) | 허용되지 않은 `list_sessions` 호출 1회. 결과 미사용 |
| `Hk_full_2` (Haiku, v2.1 2회차) | 잘못된 session_id로 `list_events` 호출 2회(오류 반환). 효과 없음 |

## 2. 사전 등록 대비 변경·추가

| 항목 | 내용 |
|---|---|
| 11문항 세트의 판별력 부족 | Opus 프롬프트 없음/v2.1 모두 11/11 통과. 이후 **어려운 질문 6개(X 시리즈)를 실행 전에 부록으로 추가 등록**하고 Haiku로 실행 |
| Haiku 프롬프트 없음 × Q 11개 | 사전 등록 목록에 없던 **추가 실행**. Opus에서 변별이 안 되어 소형 모델에서도 확인하려고 추가함 |
| Sonnet X 시리즈 | 등록 부록에는 "haiku, sonnet"으로 적었으나 **실행하지 않음**(Haiku 결과가 대부분 통과라 효과가 작다고 판단하고 생략). 미실행으로 기록 |
| 소형 모델 압축 프롬프트 | 사전 등록(6장)대로 조건 3가지 × 2회 실행. 프롬프트 없음 1회차는 비교 단계에서 이미 실행한 `A_haiku`를 재사용 |
| 모델 비교 선정 규칙 4 | 사후 추가(규칙 3에서 동률일 때 ① 정확성으로 결정). 01 보고서 6장에 사후 추가라고 명시 |
| 비용·접근성 축 | 이전 버전의 ⑤ 축을 삭제. 이번 환경에서는 측정 불가 |
| 심사자 T3 판정 | 심사자(Sonnet)가 "환산하지 않은 상대 표기"를 OK로 판정해 사전 등록 기준과 어긋남. 점수는 수정하지 않고 원점수를 유지했으며, 조정한 값을 01 보고서 5장에 병기 |

## 3. 다회전 대화의 사용자 발화

사용자 발화는 AI의 실제 응답을 읽고 이어서 작성했으며, 8개 발화의 의도(비트)만 사전에 정했다. 상태 블록 변형 실행(S1~S8)은 기준 실행(M1~M8)의 **같은 발화**를 그대로 넣었으므로, AI 응답이 달라진 경우 일부 발화가 어색할 수 있다.

## 4. 재현 방법

`raw/runs/inputs/<이름>.txt`를 서브에이전트에게 읽게 하고 "다음 어시스턴트 응답을 쓰라"고 지시한 뒤 출력과 `raw/runs/outputs/<이름>.md`를 비교한다. 모델 별칭, 지시문은 `00_preregistration.md` 1장에 있다. 확률적 생성 특성상 문구는 달라질 수 있다.
