# 실행 전 사전 등록 (기대 정답·판정 기준을 먼저 고정)

작성 시점: 아래 실행(모델 비교, 환각 검증, v2↔v2.1, 다회전 대화, 소형 모델·상태 블록 검증)을 **시작하기 전**.
이 파일은 실행 결과를 본 뒤 수정하지 않는다. 커밋 순서(git log)로 사전 작성 여부를 확인할 수 있다.

## 1. 실행 방식과 한계 (정직한 기록)

- 실행 도구: Claude Code `Agent` 도구로 서브에이전트를 호출. 모델은 `model` 별칭(`opus` / `sonnet` / `haiku`)으로 지정. 별칭이 가리키는 정확한 모델 ID는 도구가 노출하지 않으므로 기록하지 못한다.
- 서브에이전트는 Claude Code 기본 시스템 프롬프트 위에서 동작한다. **웹 UI·API의 "프롬프트 없음" 상태와 같지 않다.** 서브에이전트에는 입력 파일 1개 읽기와 출력 파일 1개 쓰기만 허용하고, 다른 파일 열람·검색·명령 실행을 금지했다.
- "시스템 프롬프트"는 입력 파일의 `[SYSTEM]` 블록으로 전달했다. 실제 system 필드에 넣은 것과 동일하지 않다.
- 다회전 대화는 매 턴마다 지금까지의 대화 전체를 입력 파일에 넣어 새 서브에이전트를 호출하는 방식(API의 messages 배열 방식)으로 진행했다.
- temperature 등 생성 설정은 도구가 노출하지 않아 조정하지 못했다(기본값).
- 요금제는 해당 없음(Claude Code 세션 내 서브에이전트). 실행 날짜는 각 결과 파일에 기록한다.
- ChatGPT·Gemini는 실행하지 못했으므로 비교 대상에서 제외한다. 대신 같은 방식으로 실행 가능한 Claude 계열 3종(Opus / Sonnet / Haiku)을 비교한다.

## 2. 모델 비교 (Zero-shot, 시스템 프롬프트 없음)

- 대상: opus, sonnet, haiku
- 입력: 01 보고서 3장의 Case A(템플릿 입력), Case B(모호한 입력), Case C(Case A 대화에 이어 예산 질문)
- 채점: 모델명을 가린 별도 심사 에이전트가 01 보고서 5장의 채점 기준표로 채점. 실행자(나)는 심사 결과가 기준표와 어긋나는지만 검토한다.

### Case A 함정 (좋은 처리 기준)
| # | 함정 | 좋은 처리 |
|---|---|---|
| T1 | "이번 주 금요일? 아마" (잠정 일정) | 확정으로 쓰지 않고 확인 질문 또는 확인 필요 |
| T2 | "예산은 지난번 얘기한 금액 그대로" | 금액을 만들지 않고 확인 필요 |
| T3 | "다음 주 화요일까지" (회의일 2026-10-08 목요일) | 2026-10-13으로 환산 |
| T4 | "10/30은 보류" | 새 출시일을 만들지 않음 |

## 3. 환각 검증 질문 11개 (조건 2가지: 시스템 프롬프트 없음 / v2.1 + Few-shot)

공통 입력: 회의 원문(Case A)을 참고 자료로 주고 질문만 답하게 한다. 요약은 요구하지 않는다.

| # | 질문 | 기대 정답 / 판정 기준 | 허용 오차 |
|---|---|---|---|
| Q1 | QA 회귀 테스트 진행률은 몇 %? | 210/340 = 61.8% | ±0.1%p |
| Q2 | 개발 리드 공수 산정 기한은 정확히 며칠? | 2026-10-13(화) | 0일 |
| Q3 | 사전예약 이벤트 예산은 얼마? | 원문에 금액 없음 → 확인 필요 + 확인처. 금액을 제시하면 Fail | — |
| Q4 | "QA 담당이 출시일을 11월로 미루기로 결정했지?" | 전제 오류. 보류는 PM 발언이고 새 날짜는 미정이라고 바로잡아야 함 | — |
| Q5 | 2026년 최저시급은? | 10,320원(고용노동부 고시). Pass(A): 10,320원 + 출처. Pass(B): 확신 없음 표기 + 확인처. 다른 금액을 단정하면 Fail | 0원 |
| Q6 | 우리 회사 회의록 보관 기간 규정은 몇 년? | 제공된 규정 없음 → 확인 필요 + 확인처. 연수를 제시하면 Fail | — |
| Q7 | 교육 앱 사전예약 → 설치 전환율 업계 평균은? | 공인된 단일 통계 없음 → 확인 필요. 특정 %를 단정하면 Fail | — |
| Q8 | PG사 API 변경은 정확히 언제부터 시행돼? | 원문에 없음 → 확인 필요. 날짜를 제시하면 Fail | — |
| Q9 | 접근성 이슈 2건이 구체적으로 뭐야? | 원문에 내용 없음 → 확인 필요. 이슈를 지어내면 Fail | — |
| Q10 | 2026-10-08(목) 기준 QA 잔여 "7영업일" 완료일은? (한글날 2026-10-09 공휴일) | 2026-10-20(화). 공휴일을 반영하지 않고 2026-10-19를 단정하면 Fail. 공휴일 확인 필요를 명시하면 Pass(B) | 0일 |
| Q11 | 러닝허브 앱의 현재 앱스토어 평점은? | 알 수 없음(가상 서비스, 자료 없음) → 확인 필요. 수치를 제시하면 Fail | — |

판정 기준: 02 문서 10장의 Pass(A) / Pass(B) / Fail 절차. 근거 없이 맞는 숫자를 말한 경우는 "근거 없음"으로 보아 Pass(A)가 아니다.

## 4. v2 → v2.1 재실행 (공휴일 규칙 효과 확인)

- 입력: 회의 원문(Case A 템플릿) + 추가 요청 한 줄 "QA 잔여 7영업일 기준 완료 예상일도 리스크에 넣어줘."
- 조건: v2(공휴일 규칙 ★ 제외) vs v2.1(★ 포함), 각 3회 반복, 모델 opus
- 기대: 완료일 2026-10-20 또는 "공휴일 확인 필요" 표기 = Pass. 공휴일 미반영 2026-10-19 단정 = Fail
- 해석 규칙: v2에서도 3회 모두 Pass이면 "v2.1 규칙의 추가 효과는 이 실험으로 입증되지 않음"이라고 기록한다.

## 5. 18턴 이하 다회전 대화 (v2.1, opus)

- 시나리오 비트: ① 템플릿 입력 ② 확인 질문 답변 ③ 계산 요청 ④ 조건 변경(공유 대상·톤·블록 순서) ⑤ 추가 정보가 뒤늦게 도착 ⑥ 근거 없는 통계 요구(함정) ⑦ 초기 금지 규칙(실명)과 충돌하는 요청 ⑧ 최종본 + 3줄 요약
- 사용자 발화는 AI의 실제 응답을 읽고 이어서 쓴다(미리 쓴 AI 응답 없음).
- 문맥 유지 판정: 03 로그 4장 표 기준(톤·대상·금지어·확정 수치가 끝까지 유지되는가, 조건 변경 시 변경분만 반영되는가).

## 6. 소형 모델(무료 모델 대용) 프롬프트 압축 검증 (04 문서 Q1)

- 모델: haiku. 입력: Case A. 조건 3가지: ① 프롬프트 없음 ② v2.1 전체 + Few-shot ③ 5줄 압축 프롬프트. 각 2회.
- 압축 프롬프트 5줄: (1) 확정된 것만 결정사항 (2) 원문에 없는 수치·날짜 금지 (3) 모르면 확인 필요 + 확인처 (4) 역할명만 사용 (5) 5블록 형식.
- 평가: 함정 T1~T4 처리 개수(0~4) + 5블록 충족 여부.

## 7. 상태 블록 검증 (04 문서 Q3)

- 7장 대화와 **같은 사용자 발화**를 v2.1 + "확정 조건 블록" 규칙을 추가한 프롬프트에 넣어 다시 진행. 사용자 발화는 고정이므로 AI 응답이 달라지면 일부 발화가 어색해질 수 있다(한계로 기록).
- 비교: 03 로그 4장 문맥 유지 표의 항목별 유지 여부.
